# 使用与复现

从源码重建结构、导入你有权使用的素材，再检查实际画面与声音。没有手机图片或采样音源时，先验证数据和网页；不要把缺图预览或静音导出写成完整作品。

## 本地预览

使用 Python 3.9 或更新版本。以下命令均在技能目录执行：

```bash
cd skills/huawei-phone-journey
python3 scripts/journey.py check
python3 scripts/journey.py serve
```

打开终端显示的网址，检查播放、定位、型号文字、年月状态和人物过界。使用本地 HTTP 服务，避免浏览器直接打开文件时的资源访问限制。普通预览不需要 npm。

默认服务地址为 `http://127.0.0.1:8780/index.html`，只绑定本机。可用 `serve --port 8781` 更换端口，用终端的中断操作停止服务。

## 手机图片

目录中保留图片来源线索与本地目标路径，图片文件本身没有入库。工具支持显式获取和本地导入，另需 Pillow：

```bash
python3 -m pip install pillow
python3 scripts/journey.py fetch --help
python3 scripts/journey.py import-images --help
```

选择目录里的精确 ID，用 `fetch --ids` 指定少量记录，或用 `--all` 选择入片名单；显式传入 `--yes` 才会访问图片原来源。例如：

```bash
python3 scripts/journey.py fetch --ids huawei-p30pro-93caa431 --yes
python3 scripts/journey.py import-images --from my-images
```

本地导入默认寻找以记录 ID 命名的 PNG、JPG、JPEG 或 WebP 文件。文件名不同则提供 `--map mapping.json`，内容为 ID 到输入目录内相对文件路径的对象。不可使用越出输入目录的路径。

先用少量明确身份的图片检查流程，再决定是否批量导入。下载或导入后，核对精确型号、变体、尺寸和完整性。不要把网页技术插图或错误版本自动升为生产素材。

工具将图像转为只含像素的 PNG 副本，存入 `assets/phones`；用户提供的输入原图不修改。转存包括按 EXIF 方向转正和移除元数据，因此不承诺副本与源文件的字节一致。保留原幅比例和可见水印，不改绘手机。`serve`、导入和构建时会生成 `assets/inventory.json`，网页只加载清单中的本地图片。

显示上限按原幅允许使用的长边设置。来源不可访问时保持缺图提示，不猜地址或绕过访问限制。来源 URL 用于追溯，不是版权授权证明。

## 音源与音频

音频重演奏另需 NumPy、SciPy 与 SoundFile：

```bash
python3 -m pip install numpy scipy soundfile
python3 scripts/audio.py --help
```

音频脚本需要用户自己的样本库配置。五类乐器各至少一份样本，另需三个已经准备好的鼓片段；文件必须位于配置文件目录内，不能使用绝对文件路径或通过链接越出目录。格式见[音源配置模板](../skills/huawei-phone-journey/examples/audio-bank.json)，模板不含音频。

`instrument` 是乐器名，`file` 是配置目录内的文件名，`rootMidi` 与 `velocity` 是采样根音和力度；可选 `f0Hz` 为实测基频。模板中的文件名和 MIDI 值仅为示例，必须按你自己的音源填写。一个样本覆盖宽音域可能产生明显变调痕迹，较密的音高与力度映射更合适。配置和采样文件留在本地。

```bash
python3 scripts/audio.py --bank my-samples/bank.json --out output/试听.wav --seconds 15
python3 scripts/audio.py --bank my-samples/bank.json --out output/混音.wav
```

输出为 48 kHz、双声道、24 位 PCM WAV；默认演奏整个乐谱，`--seconds` 仅生成从零开始的短试听。合成低音与艺术气流由程序生成，不是手机机械声实录。脚本做采样峰值控制，没有完成最终响度与真峰母带处理。

生成后实际监听开头、每个章节交接、重点过界和结尾，再检查总时长、声道、采样率、响度与峰值。源码和乐谱可重建演奏结构，不能保证不同采样得到同一音色或同一母带字节。

## 构建与视频导出

```bash
npm install
python3 scripts/journey.py build
npm run check
npm run render
```

先安装可选依赖，再构建并运行 npm 检查与导出。构建复制本地 GSAP 到工程中，npm 命令针对 `output/project` 执行，默认影片为 `output/journey.mp4`、30 帧/秒。静态构建也可用于部署可访问的网页。可选工具版本为 HyperFrames 0.8.135、GSAP 3.14.2。

可先生成短段进行导出检查：

```bash
python3 scripts/journey.py build --seconds 12
npm run check
npm run render
```

`--start` 选择片内开始秒数，`--seconds` 选择长度；长度须对齐 30 帧/秒边界，默认覆盖完整旅程。带声音时用 `build --audio output/混音.wav`；可选 WAV、MP3 或 M4A，目前只支持 `--start 0` 的有声构建。它不会代替音轨时长、响度和真峰核验。

导出前确认所需图片已导入，音频按实际制作状态接入。若素材仍缺失，导出只用于技术预览。静态托管或对外上传前也要确认素材许可；本地可访问不等于允许公开部署。

## 验证与结果说明

数据检查应核对目录记录、入片 ID 与时间轴的对应关系，以及区间、帧率和时长。网页检查之后，还需要实际查看不同年代、材质过界、重点手机和首尾画面。

完整视频应通过媒体探测与全片解码，再从该视频抽帧；不要用另一个渲染器的预览代替成片证据。声音应实际监听，不能仅凭事件数量判断音乐质量。

报告至少说明：使用的目录和时间轴版本、导入的图片与音源、运行环境、已执行命令、实际输出、仍缺失的素材和待人工判断项。检查通过、导出成功、听感通过与作者接受是不同结果。

## 修改与回退

先复制技能目录或保存版本，再调整自己的资料与素材。目录、时间轴、乐谱相互关联，修改入片名单后需要重新检查对应 ID 与时间区间。

回退只需恢复本次修改的源码和数据；导入图片、音源和输出可单独保留。不要覆盖原始手机图片或原始音源，不要将私人路径与素材文件提交到公共仓库。
