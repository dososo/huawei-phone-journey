# 设计与原理

这套动画把手机图片当作旅程中的画板。同一个角色在连续空间中前进，进入下一块画板时，身体不同部位按实际空间位置换成相应媒介。观众同时看到产品外观的变化和角色表面的变化。

## 数据、时间与画面

`skills/huawei-phone-journey/data/catalog.json` 保存机型记录与来源线索，`journeyIds` 决定进入旅程的记录。当前两者分别是 1106 条与 451 项。资料记录可能包含同系列版本、别名及待核信息，不等于独立型号总数。

`timeline.json` 保存九章、序幕、章节门、节点与片尾段落。当前帧率 30 帧/秒，总长 772.7 秒、23181 帧。普通节点约 1.6 秒，重点节点有更长的观看时间。`arrival` 与 `crossingPeak` 是到达与过界声音的时间锚点；不能把展示用的整秒章节导航当成这些精确时点。

日期按年、月推进。推断年月、来源冲突与待复核状态保留在目录中，并随记录展示。某条记录的排序值仅代表当前资料组织选择；不能由该位置反推出官方精确发布日期。

## 同一个人，多个表面

`src/hero.js` 独立绘制人体姿态和不同材质。不同表面使用同一时间和姿态输入，保证同一帧的头、手、躯干、腿与披风位置一致。

`src/journey.js` 绘制世界空间中的图片画板，并按画板范围裁切人物表面。因此过界时会出现半身玻璃、半身金属等连续状态；这来自空间裁切，不是把整个人在某一时刻直接换色。

材质差异需要同时体现明暗、结构线、反射、片层和透明感。图像风格到人物媒介的映射是一种创意表达，不代表手机使用了相同材料，也不证明任何硬件技术事实。

## 九章节奏

`src/compact.js` 将连续旅程组织为九章结构，`src/app.js` 管理绘制与交互，`src/player.js` 驱动普通网页的播放时钟。构建导出工程时排除 `player.js`，由 GSAP 接管确定性的逐帧定位与渲染，避免网页播放时钟同时推进。章节门用于年代转换，序幕与片尾提供独立观看节奏。

手机画板按完整原幅比例和记录中的显示尺寸上限绘制，不依赖某三款图片的固定裁切坐标。完整正背组合图按完整组合呈现，不截取其中一台冒充单视角；历史小图不因进入大画板而被称作高清图。人物可能在前景遮挡部分图片，实际可辨认程度仍需看图判断。

缺失图片显示明确提示，不绘制假手机替代。没有图片时可以验证时间轴和人体运动，但无法验收真实手机外观。

## 乐谱与声音

`data/score.json` 保存 2446 条乐谱事件，并有重点提示与轻空气层的编排数据。当前主题速度为 75 BPM，九章分别调整配器与密度；贝母段以钢琴和暖垫留白，折叠段让弦乐与气流返回。

乐谱数据不包含商业采样。`scripts/audio.py` 使用用户提供的音源配置重演奏；不同采样、音高映射和混音设置会改变音色与听感。事件和时点核对不能替代实际监听，亦不保证复现某个已发布母带。

## 复现的层次

| 层次 | 可核验的内容 | 仍需另外确认 |
| --- | --- | --- |
| 数据 | 唯一身份、入片名单、时间区间、日期标记 | 历史来源的真实性与冲突消歧 |
| 网页 | 脚本加载、播放定位、缺图提示 | 图片可辨性、角色审美与阅读体验 |
| 导出 | 分辨率、帧数、完整解码和文件哈希 | 实际成片画面、音画同步与听感 |
| 发布 | 选用的素材与用途记录 | 素材授权、平台账号权限与作者验收 |

项目提供可检查的结构与工具。不同字体、浏览器、图片和音源会产生不同输出，因此不承诺跨环境像素一致或原片字节相同。
